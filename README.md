# SafeHome

AI 기반 부동산 거래 안전 플랫폼

## 개발 환경

- Windows
- Python 3.12.10
- Java 21 LTS
- Node.js 24 LTS (`frontend/.nvmrc` 기준)
- Docker
- PostgreSQL 17
- Redis 8

## 로컬 실행

Docker Desktop이 실행된 상태에서 저장소 루트(`D:\projects\safeHome`)의 PowerShell에서 실행합니다. Java 21·Node.js 24와 Frontend 의존성(`npm ci`)이 준비되어 있어야 합니다.

```powershell
# PostgreSQL, Redis, Integration Server, Backend, Frontend 시작
.\scripts\start-dev.ps1

# 전체 상태 확인
.\scripts\status-dev.ps1

# Frontend, Backend, Integration Server, PostgreSQL, Redis 중지
.\scripts\stop-dev.ps1
```

PostgreSQL과 Redis를 계속 실행하려면 다음 옵션을 사용합니다.

```powershell
.\scripts\stop-dev.ps1 -KeepInfrastructure
.\scripts\start-dev.ps1 -SkipInfrastructure
```

### 공유 설정과 실행 순서

- 시작 스크립트는 `-ConfigFile` → 현재 `SAFEHOME_CONFIG_FILE` 환경변수 → `D:\safehome-data\config\safehome-local.yml` 순서로 공유 설정 파일을 선택합니다. 파일이 없으면 서버를 시작하지 않고 오류를 표시합니다.
- 선택한 설정은 Backend와 Integration Server에 함께 전달합니다. 키·토큰·암호는 설정 파일에서 관리하며 저장소에 넣지 않습니다.
- PostgreSQL·Redis 기동 → Integration Server 시작 및 정상 응답 확인 → Backend·Frontend 시작 및 정상 응답 확인 순서입니다.
- 이미 정상 실행 중인 서버는 재시작하지 않습니다. 소스나 설정 변경을 반영하려면 먼저 종료한 뒤 다시 시작합니다. `-KeepInfrastructure`와 `-SkipInfrastructure`로 DB·Redis를 유지할 수 있습니다.
- 기본 개발 포트 기준으로 관리합니다. 별도 검증 환경의 8180 Backend·5174 Frontend는 관리하지 않습니다.

```powershell
# 다른 공유 설정 파일을 지정할 때
.\scripts\start-dev.ps1 -ConfigFile 'D:\safehome-data\config\safehome-local.yml'

# 코드·설정 변경 후 애플리케이션 재시작 (DB·Redis 유지)
.\scripts\stop-dev.ps1 -KeepInfrastructure
.\scripts\start-dev.ps1 -SkipInfrastructure
```

| 구성 요소 | 주소 | 상태 확인 |
| --- | --- | --- |
| Frontend | <http://localhost:5173> | HTTP 응답 |
| Backend | <http://localhost:8080> | /actuator/health |
| Integration Server | <http://localhost:8090> | /actuator/health |
| PostgreSQL | 127.0.0.1:5432 | Docker 컨테이너 health |
| Redis | 127.0.0.1:6379 | Docker 컨테이너 health |

`status-dev.ps1`은 5개 구성 요소를 모두 확인하고 하나라도 준비되지 않으면 종료 코드 1을 반환합니다. health 응답은 서버 생존 확인이며 외부 API 인증·조회 성공까지 보증하지 않습니다.

로그는 저장소의 `.runlogs/`에 `backend.*.log`, `frontend.*.log`, `integration.*.log`로 기록됩니다. 실행 관리용 PID는 `.run/`에 저장합니다. 기동 실패 시 해당 로그를 확인하되 키·토큰·개인정보를 공유하지 마세요. 종료 스크립트는 기본 포트의 프로세스도 종료하므로 해당 포트를 다른 프로그램에 사용하지 마세요. Docker 컨테이너를 중지해도 DB 볼륨은 삭제하지 않습니다.

### PDF 판독 모델

2026-10-23 로컬 공유 설정의 `safehome.openai.model`을 `gpt-6.1-sol`로 변경해 비교 검증한다. 등기사항증명서와 건축물대장 PDF가 이 설정을 함께 사용한다. 설정 파일 위치는 `D:\safehome-data\config\safehome-local.yml`이며 실제 키·토큰은 문서나 저장소에 넣지 않는다. 저장소의 기본값·테스트 기준 `gpt-4.1`은 이전 모델로 복구할 수 있도록 유지한다.

- 모델 설정은 Backend 기동 때 읽는다. 정상 실행 중 `start-dev.ps1`만 다시 실행해도 설정은 갱신되지 않는다. Backend 재시작이 필요하다. 아래 명령은 DB·Redis를 유지하고 개발 애플리케이션 전체를 재시작한다.

```powershell
.\scripts\stop-dev.ps1 -KeepInfrastructure
.\scripts\start-dev.ps1 -SkipInfrastructure
```

- Sol에는 `reasoning.effort=low`와 추론/결과 합계 `max_output_tokens=25000`을 적용한다. `none`을 사용하지 않는다. 이전 `gpt-4.1` 요청은 추론 옵션 없이 기존 출력 한도(등기사항 3000 / 건축물대장 8000)를 유지한다.
- 두 모델 모두 Responses API, 고해상도 PDF 입력(`detail=high`), `store=false`, strict JSON schema, 180초 제한, 자동 유료 재시도 금지를 유지한다. 불완전한 출력은 판독 완료로 처리하지 않는다.
- Sol의 이미지 입력·구조화 출력 지원과 계정의 모델 조회 가능 여부는 확인했다. 이것이 실제 한국어 문서 판독 정확성·과금 추론 성공까지 검증했다는 의미는 아니다. 고유명칭·동/층/호·권리/말소·금액과 복합 대장의 출처·행 누락을 실제 파일로 비교해야 한다. 이전 모델의 실제 샘플 결과를 새 모델 결과로 간주하지 않는다.
- 공식 표준 텍스트 단가는 100만 토큰당 Sol 입력 $2 / 출력 $10, GPT-4.1 입력 $2 / 출력 $8이다(2026-10-23 확인). 추론 토큰과 PDF 이미지 처리량도 비용에 영향을 주므로 파일당 비용이 같다고 보지 않는다. 출력 한도는 매번 소비하는 토큰 수가 아니다.
- 복구할 때는 같은 공유 설정에서 모델을 `gpt-4.1`로 되돌리고 Backend를 재시작한다. 기존 판독/실패 이력은 자동 변경하거나 재처리하지 않는다.

출처: [모델 지원·가격](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [PDF 입력](https://developers.openai.com/api/docs/guides/file-inputs), [추론 출력 예산](https://developers.openai.com/api/docs/guides/reasoning), [기존 모델 가격](https://developers.openai.com/api/docs/models/gpt-4.1).

### 판독 오류 확인

일반 개발 서버의 판독 오류 기록은 `.runlogs/backend.out.log`에서 먼저 확인합니다. 실행 오류는 `backend.err.log`도 확인합니다. 문서 번호와 매물 번호는 서로 다를 수 있습니다.

```powershell
Select-String -Path .\.runlogs\backend*.log -Pattern 'documentId=54|REGISTRY_ADDRESS_MISMATCH'
```

- 판독 실패 로그에는 문서/매물 번호, 오류 코드·예외 종류, 실패 단계, 처리 시간, provider/model, 파일 크기·SHA-256을 기록합니다. 예외 메시지·키·토큰·PDF 원문·소유자 정보는 기록하지 않습니다.
- 등기사항증명서 추출값 검증 실패는 `Registry validation rejected` 로그의 `diagnostic=` 경로에서 비공개 JSON 근거를 확인합니다. 주소 불일치이면 `lotMatches`·`roadMatches`도 로그에 표시합니다.
- 기본 개발 저장소 기준 위치는 `D:\safehome-data\registry-documents\diagnostics\registry-validation\document-<문서번호>-<고유값>.json`입니다. 실제 경로는 `safehome.document.storage-root` 설정 아래이며 JSON은 웹 API로 제공하지 않습니다.
- 주소 불일치 JSON에는 등록 기본/상세/전체 주소, AI가 읽은 지번·도로명 주소, 각각의 정규화 값과 일치 여부가 있습니다. 다른 추출 검증 오류는 값 존재·형식 여부와 개수 등 제한된 메타데이터만 기록합니다.
- 시도별 파일은 덮어쓰지 않습니다. 파일 저장이 실패하면 `diagnostic=UNAVAILABLE`을 기록하고 원래 판독 실패 상태를 유지합니다. 기록을 위한 AI 자동 재호출은 없습니다.
- 보완 이전 실패의 AI 추출값은 소급 복원하지 못합니다. 진단 파일에 주소가 있으므로 비공개 PDF와 같은 접근 권한으로 관리하고 외부에 그대로 공유하지 마세요.

스크립트 실행 정책 오류가 발생하면 현재 터미널에서만 다음과 같이 실행할 수 있습니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-dev.ps1
```

수동으로 실행하는 경우 PostgreSQL과 Redis는 다음 명령으로 시작합니다.

```powershell
docker compose up -d
```

Frontend 전체 품질 점검은 다음 명령으로 실행합니다.

```powershell
cd frontend
npm ci
npm run check
```

## 2026-10-23 완료 후 관리·권리 누락·소유지분 표시 보완

- 본인 매물은 판독·분석 완료 후에도 수정/삭제할 수 있다. 등기·건축물 작업 실행 중에는 충돌을 막기 위해 제한한다. 삭제는 목록에서 숨기는 방식이며 문서·판독·계약·분석 이력은 보존한다. 운영 전 실제 파일 삭제와 이력 보존 기간·복원 정책을 확정한다.
- 거래 조건 변경은 기존 분석을 최신으로 간주하지 않는다. 주소/상세주소 변경 시 기존 이력은 보존하고 등기사항증명서 재판독을 요구한다. 분석 입력 지문과 분석 엔진 1.1 버전으로 재분석 필요 여부를 판단한다.
- 활성 전세권은 계약 미등록 상태에도 위험요소로 포함한다. 계약 기준일이 없으면 선순위를 확정하지 않는다. 전세권의 존재만으로 전입세대·실제 점유·확정일자를 확인했다고 표시하지 않는다. 소유관계 검토는 계약 권한과 원문 확인을 안내하며 공동소유 형태를 인원수만으로 단정하지 않는다.
- 모든 현재 소유자/공유자 행과 원문 지분을 별도로 보존하도록 판독 계약을 보완했다. 화면에는 '12분의 1'처럼 문서에 표기된 지분만 표시한다. 백분율·나머지 지분을 표시하거나 특정 소유자에게 배분하지 않는다. 누락된 원문은 '원문 확인 필요'로 안내하며 사용자 진술로 기존 판독 데이터를 보정하지 않는다.
- V22는 삭제 시각·분석 입력 지문·원문 지분 열을 추가하고 내부 비율 정밀도를 확장한다. 기존 판독 소유자의 누락을 소급 복구하는 migration이 아니다. 기존 분석은 보존하며 새 기준 재분석으로 활성 전세권 등을 반영한다. 실제 누락된 소유자 행/원문 지분 복구는 사용자 동의 후 재판독 결과로 확인해야 한다.
- 판독 완료 문서는 별도 비용·외부 전송 동의 후 수동 재판독할 수 있다. 원본과 이전 결과를 보존하고 새 판독 이력을 만든다. 재시작 중단 작업은 실패로 전환하며 유료 AI로 자동 재전송하지 않는다. 건축물대장 파일 등록/판독 영역으로 이동하는 바로가기를 추가했다.
- 검증: 별도 테스트 DB와 모의 판독으로 Backend 관련 28개 검사, Frontend 77개 검사·lint·배포 빌드, Backend JAR 빌드 통과. 실제 AI 재판독·공공 API 재조회는 실행하지 않았다. 5명 원문 지분 보존·전세권 포함·완료 매물 수정·숨김 삭제·재판독 동의와 이력 보존을 검사했다. 실제 문서의 누락 복구 정확성은 아직 검증하지 않았다. 기존 미커밋 변경을 보존하며 커밋·push하지 않는다.

## 2026-10-26 매물 단독 등록·상세 문서 분석 기능 연결

- 화면 리뷰를 마치고 실제 기능을 연결했다. 신규 매물은 POST /api/listings JSON으로 매물정보만 저장한다. 주소검색 근거를 필수 검증하며 문서/물건 스냅샷은 생성하지 않는다. 기존 매물 수정/삭제·분석 이력을 보존한다. 이전 기록의 '화면 검토용/버튼 미연결'은 당시 상태다.
- 상세화면에서 유효한 PDF 선택 후 '등기사항증명서 분석'을 누르면 전송 대상(OpenAI)·소유자 정보 포함·비용 안내를 확인한다. 취소하면 전송하지 않는다. 승인하면 POST /api/listings/{id}/registry-analysis multipart(registryPdf, consent=true, requestId=UUID)로 새 문서를 등록하고 커밋 후 기존 비동기 분석기로 전달한다. 브라우저는 파일 등록 중/문서 분석 중 상태를 표시하고 완료되면 상단 결과를 갱신한다. 안전성 분석은 별도 카드에서 실행한다.
- 요청 UUID는 매물 잠금과 DB 고유 제약으로 멱등 처리한다. 응답 유실 후 동일 요청을 다시 보내면 같은 작업 상태를 반환한다. 다른 UUID의 실행 중 요청은 409로 거절한다. 새 문서 분석이 실패해도 이전 문서·소유자·권리·위험 분석은 보존하고 화면에 이전 결과임을 표시한다. 사용자 새 시도만 별도 작업을 만든다. 유료 자동 재시도·기존 문서 자동 재분석은 없다.
- 파일은 최대 10MiB·50페이지·비암호화 PDF를 서버에서도 검사한다. 새 경로는 확장자/MIME/PDF 내용을 검사하며 동의 없는 요청·타인 매물·삭제된 매물·실행 중 중복을 거절한다. 파일 저장 후 트랜잭션 실패 시 새 파일만 정리한다. 기존 /registry-documents/listings 통합 등록 API는 호환성을 위해 유지하지만 화면에서는 사용하지 않는다.
- V23은 문서 요청 UUID·동의 시각과 소유자 원문 분류(OWNER/CO_OWNER/UNKNOWN)·갑구 순위번호·주소·거래가액을 추가한다. 기존 행은 UNKNOWN으로 보존한다. 추출 schema·검증·저장·소유자 전용 조회·화면을 함께 연결했다. 소유자/공유자는 명시적 원문 표기로만 구분하며 행 순서·지분 크기·대지권 비율로 추정하지 않는다. 현재 유효한 모든 소유자·공유자는 위험 분석 입력에 포함된다.
