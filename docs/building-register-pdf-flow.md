## 2026-10-23 완료 후 관리·권리 누락·소유지분 표시 보완

- 본인 매물은 판독·분석 완료 후에도 수정/삭제할 수 있다. 등기·건축물 작업 실행 중에는 충돌을 막기 위해 제한한다. 삭제는 목록에서 숨기는 방식이며 문서·판독·계약·분석 이력은 보존한다. 운영 전 실제 파일 삭제와 이력 보존 기간·복원 정책을 확정한다.
- 거래 조건 변경은 기존 분석을 최신으로 간주하지 않는다. 주소/상세주소 변경 시 기존 이력은 보존하고 등기사항증명서 재판독을 요구한다. 분석 입력 지문과 분석 엔진 1.1 버전으로 재분석 필요 여부를 판단한다.
- 활성 전세권은 계약 미등록 상태에도 위험요소로 포함한다. 계약 기준일이 없으면 선순위를 확정하지 않는다. 전세권의 존재만으로 전입세대·실제 점유·확정일자를 확인했다고 표시하지 않는다. 소유관계 검토는 계약 권한과 원문 확인을 안내하며 공동소유 형태를 인원수만으로 단정하지 않는다.
- 모든 현재 소유자/공유자 행과 원문 지분을 별도로 보존하도록 판독 계약을 보완했다. 화면에는 '12분의 1'처럼 문서에 표기된 지분만 표시한다. 백분율·나머지 지분을 표시하거나 특정 소유자에게 배분하지 않는다. 누락된 원문은 '원문 확인 필요'로 안내하며 사용자 진술로 기존 판독 데이터를 보정하지 않는다.
- V22는 삭제 시각·분석 입력 지문·원문 지분 열을 추가하고 내부 비율 정밀도를 확장한다. 기존 판독 소유자의 누락을 소급 복구하는 migration이 아니다. 기존 분석은 보존하며 새 기준 재분석으로 활성 전세권 등을 반영한다. 실제 누락된 소유자 행/원문 지분 복구는 사용자 동의 후 재판독 결과로 확인해야 한다.
- 판독 완료 문서는 별도 비용·외부 전송 동의 후 수동 재판독할 수 있다. 원본과 이전 결과를 보존하고 새 판독 이력을 만든다. 재시작 중단 작업은 실패로 전환하며 유료 AI로 자동 재전송하지 않는다. 건축물대장 파일 등록/판독 영역으로 이동하는 바로가기를 추가했다.
- 검증: 별도 테스트 DB와 모의 판독으로 Backend 관련 28개 검사, Frontend 77개 검사·lint·배포 빌드, Backend JAR 빌드 통과. 실제 AI 재판독·공공 API 재조회는 실행하지 않았다. 5명 원문 지분 보존·전세권 포함·완료 매물 수정·숨김 삭제·재판독 동의와 이력 보존을 검사했다. 실제 문서의 누락 복구 정확성은 아직 검증하지 않았다. 기존 미커밋 변경을 보존하며 커밋·push하지 않는다.

## 2026-10-22 실제 AI 판독 6회 검증·누락 차단 보완

- 사용자 승인으로 실제 PDF 11개·27페이지를 총 6회 판독했다. 단독 전유부 1건은 기본 검사를 통과했지만 5개 복합 입력에서는 표제부 누락과 파일 번호 혼동이 발견됐고 복층의 추가 층 면적도 누락됐다. 실제 결과를 모두 정상으로 보고하지 않는다.
- 입력 PDF별 결과 존재·원본 파일 종류·증거 페이지 검사를 추가하고 복층 행 보존 지시·동일 호실 정규화와 실패 안내를 보완했다. 저장된 응답 재검증으로 누락된 5건 차단을 확인했다. 추가 외부 호출 없이 Backend 31개·Frontend 75개 검사와 빌드를 통과했다.
- 추가 승인한 07·08의 2회를 실행했다(전체 8회). 07은 기본 검사를 통과했고 08은 원본 파일 종류와 추출 종류 불일치로 차단됐다. 복층·부분 시정의 실제 추출 품질은 미해결이며 현재 개발의 남은 보완 항목이다. 자동 재시도하지 않았다. 이전 기록의 '실제 AI 미실행'은 1차 합성 검사 당시 기록이다. 세부 결과·한계는 [실제 AI 판독 검증](building-register-ai-validation-20261022.md)을 따른다.

## 2026-10-22 최종 확정·구현: 전유부 필수, 표제부 선택

- 집합건물(APARTMENT·OFFICETEL·VILLA·MULTI_UNIT)의 건축물대장 **파일 판독을 신청할 때만 전유부를 필수**로 받는다. 표제부·총괄표제부는 선택 보완 자료다. 단독·다가구(HOUSE·DETACHED_HOUSE·MULTI_FAMILY)는 일반건축물대장이 필수다. 기타/미분류는 전유부 또는 일반건축물대장을 받는다.
- 건축물대장 점검 항목 자체는 선택이다. 자료 미등록·판독 실패·필수 대장 누락 때문에 기존 등기사항증명서 기반 안전성 분석을 차단하지 않는다. '필수'를 매물 등록·안전성 분석 전체의 필수 조건으로 해석하지 않는다.
- 화면에서 필수 문서와 선택 문서 입력 칸을 나누며 선택 문서만으로 등록할 수 없다. 전유부만으로 등록·판독할 수 있고 선택 문서 미첨부를 오류로 처리하지 않는다. 앞면·뒷면·추가 장을 포함한 전체 PDF를 안내한다. 여러 문서가 합쳐진 PDF는 필수 칸에 등록 가능하다. 합계 최대 5파일·10MiB·50페이지는 두 칸 전체에 적용한다.
- 브라우저 입력 칸은 사용자의 선택 구분이며 실제 문서 종류의 확정 근거가 아니다. 서버가 저장된 매물 유형과 AI 추출된 실제 문서 종류를 확인한다. 필수 유형이 없으면 FAILED로 저장하고 새 파일 묶음을 요구한다. 잘못된 문서의 재판독을 막기 위해 같은 묶음의 시작 API도 409로 거절한다. 업로드만으로 AI를 호출하지 않고 동의 후 판독하는 기존 절차는 유지한다.
- 문서 종류는 AI 판독 후 검증하므로 잘못 선택한 문서의 첫 판독 비용까지 사전 차단하는 기능은 아니다. 기존 표제부만의 PARSED 이력은 원본 상태를 변경하지 않고 화면에서 필수 문서 보완 필요로 표시한다. 자동 재판독·데이터 보정은 하지 않는다.
- 공개 응답 Review에 `requiredDocumentType`(EXCLUSIVE / GENERAL / EXCLUSIVE_OR_GENERAL)을 추가했다. 해당 이력의 저장된 비교 문맥에서 산정한다. 기존 업로드 multipart `files` 계약과 DB 구조는 유지하며 추가 migration은 없다. 필수 문서 누락 코드는 EXCLUSIVE_REGISTER_REQUIRED / GENERAL_REGISTER_REQUIRED / PRIMARY_REGISTER_REQUIRED다.
- 전유부 표지와 선택 문서 표지를 구분해 요약한다. 표제부에 표시가 없더라도 전유부 표시를 취소하지 않는다. 선택 문서에만 표시가 있으면 대상 호실 관련성의 추가 확인을 안내한다. 긍정적인 자료 일치 요약에는 필수 문서 존재가 필요하다.
- 샘플에서 확인한 여러 장·좌우 구획에 걸친 문장, 사건 참조, 부분 시정/해제·미시정 보존을 판독 지시에 추가했다. 사건별 구조화·자동 연관 판정·중복 제거를 완성한 것은 아니며 실제 발급 PDF의 AI 정확성 검증은 아직 별도 과제다. 위험 점수는 변경하지 않는다.
- 검증: 별도 DB `safehome_stage6_history_test`와 합성 PDF·모의 AI로 Backend 관련 26개 검사와 JAR 빌드를 통과했다. Frontend 75개 검사·lint·배포 빌드도 통과했다. 실제 OpenAI·공공 API·기존 등기사항 재판독은 실행하지 않는다. 기존 미커밋 변경을 보존하고 커밋·push하지 않는다.

일반 개발 Backend(8080)를 최신 JAR로 재시작하고 HTTP 200을 확인했다. 사용자 로그인 후 실제 매물 49에서 필수 전유부·선택 보완 문서 입력칸과 파일 미선택 시 등록 비활성화를 확인했다. 실제 PDF 업로드·판독 버튼은 누르지 않았다.

# 건축물대장 PDF 판독·자료 대조 — 2026-10-22

## 2026-10-22 샘플 검토에 따른 범위 확정

- 집합건물의 전유부 단독 판독은 허용한다. 다만 **건물 단위 문서 점검에는 해당 동 표제부도 필요**하며 전유부만으로 그 범위를 완료 처리하지 않는다. 총괄표제부는 보완 자료이고 해당 동 표제부의 대체 자료가 아니다.
- 발급받은 뒷면·추가 장·변동사항까지 전체를 첨부한다. 건축물대장 선택 항목의 미첨부가 전체 안전성 분석을 막지는 않는다.

- 상세 결정과 후속 항목은 [샘플 검토 및 첨부 범위 기준](building-register-sample-review.md)을 따른다. 아래의 '표제부 추가 권장'은 업로드 허용 정책이며 건물 단위 확인 범위를 생략할 수 있다는 뜻은 아니다.

## 사용자 흐름과 확인 범위

세움터에서 사용자가 발급한 PDF를 매물 상세에 첨부한다. 자동 로그인·발급·스크래핑을 수행하지 않는다. 전유부만 첨부해도 판독 가능하며 표제부를 함께 첨부하면 건물 전체의 기재사항도 확인할 수 있다. 단독·다가구는 일반건축물대장을 안내한다. 변동사항이 있는 뒷면·추가 장을 포함해 발급받는 것이 좋다.

- 전유부: 해당 호실의 동·층·호, 용도, 면적과 첨부된 페이지의 관련 기재를 추출한다.
- 표제부: 건물 전체 용도와 관련 변동사항·위반 기재를 확인하는 보완 자료다. 현재 구현은 기재 추출 및 주소·용도 대조 범위이며 모든 건물 현황 항목의 자동 비교는 아니다.
- 파일 등록과 AI 판독 시작을 분리한다. 등록만으로 외부 전송하지 않는다. 최신 묶음에 대해 OpenAI 전송 동의 후 사용자가 시작해야 한다.
- PDF 최대 5개, 합계 10MiB, 합계 50페이지, 암호 없는 파일만 허용한다. 프론트엔드에서 비PDF를 먼저 차단하고 서버에서 실제 PDF·암호·페이지를 재검사한다. 기존 요청 상한 11MB 안에서 처리한다.

## 결과 표시 원칙

- 비교 가능한 항목이 일치하고 모든 추출 항목에서 표시가 보이지 않을 때: **자료 대조 일치 · 첨부 문서에서 위반 표시 미확인**.
- API·등기사항·문서 정보 부족은 개별 항목에 '비교 정보 부족'으로 표시한다. 일치 표시는 실제 비교 가능한 항목에 한한다.
- 전유부만 제출한 경우 표제부 미첨부로 건물 전체 현황·변동사항을 문서로 확인하지 못했다는 범위를 표시한다. 총괄표제부는 해당 동 표제부를 대체하지 않는다.
- 현재 위반 관련 표시가 추출되면 근거 페이지를 표시한다. 표시 주장에 관련 문구 근거가 없으면 확인 불가로 둔다. 과거·말소 기재는 보존하고 추가 확인 대상으로 표시한다.
- 주소·등록 유형과 용도·호실·API 호실 등을 대조한다. 등록 상세주소에 동이 있으면 동도 대조한다. 다른 동의 동일 호수는 자료 일치로 결론내리지 않는다.
- 면적·층 표기는 추출해 제시한다. 현재 면적의 API/등기사항 간 수치 비교, 층 전체 정규화 비교, 도면·현장 비교와 문서 진위 확인은 구현하지 않았다.
- '위반 없음', '불법증축 없음', '안전 보증'으로 표시하지 않는다. PDF 전체에 없는 현장 상태나 아직 행정 기재되지 않은 위반을 추정하지 않는다.

## API와 저장

기본 경로: `/api/listings/{listingId}/building-register`.

| 요청 | 기능 |
|---|---|
| GET 기본 경로 | 최신 묶음과 최대 50개 이력 요약 |
| POST 기본 경로, multipart files | 새 PDF 묶음 등록, 자동 판독 없음 |
| GET /{reviewId} | 특정 묶음 상태와 결과 |
| POST /{reviewId}/processing, {consent:true} | 최신·유효 묶음의 판독을 명시적으로 시작 |
| GET /{reviewId}/files/{index} | 소유자만 원본 PDF 다운로드 |

V21 `building_register_reviews`에 파일 참조·해시, 비교 대상 스냅샷, 처리 상태, 추출·대조 결과, 동의 시각, 모델·공급자, 시각을 저장한다. 기존 V20 migration은 변경하지 않았다. PDF는 기존 비공개 암호화 저장소를 사용한다. DB·키·실제 문서는 Git에 넣지 않는다.

상태: UPLOADED / PROCESSING / PARSED / FAILED / SUPERSEDED. 소유권을 모든 경로에서 검사하고 파일 접근 경로·해시는 응답에 포함하지 않는다. 업로드 시 비교 대상과 실행·완료 시 최신성을 확인한다. 새 묶음이나 비교 정보가 변경되면 늦은 결과는 현재 결과를 덮지 않는다. 동일 묶음의 중복 실행을 제한한다.

등기사항증명서·스냅샷·기존 위험 분석을 변경하지 않는다. 건축물대장 결과를 위험 점수에 자동 합산하지 않는다. 공공 API 원천 내용 전체를 이 기능에서 재수집하지 않는다. 현재 API와 비교하는 세부 정보는 저장된 식별 호실과 상태이며, API의 모든 면적·용도 항목과 일치했다고 표시하지 않는다.

## 외부 전송과 장애

기존 서버 측 OpenAI 설정·모델을 사용한다. Responses API에 이 묶음의 PDF만 보내며 `store:false`, 구조화 출력으로 처리한다. 기존 등기사항 PDF를 함께 전송하지 않는다. 원본 문서 내용은 명령이 아닌 데이터로 취급한다. 소유자 개인정보를 추출하지 않도록 지시하며 추출 문자열의 완전한 주민등록번호 형태를 추가 마스킹한다. AI 개인정보 누락 방지가 완전하다는 보장은 아니다.

유료 AI 호출은 자동 재시도하지 않는다. 재시작 시 PROCESSING은 중단 실패로 표시하며 자동 재전송하지 않는다. 실패 후 동의와 시작 버튼으로 새 시도를 요청할 수 있다. 작업 큐는 단일 인스턴스에서 1개 실행·20개 대기다. 오류 본문·키·PDF 내용은 출력하지 않는다.

## 검증과 남은 작업

합성 PDF·모의 AI·로컬 HTTP와 별도 DB `safehome_stage6_history_test`에서 Backend 관련 22개 검사를 통과했다. 판독 동의·소유권·중복 실행·기존 분석 보존·자료 교체 시 늦은 결과 차단·재시작 자동 미전송·삭제 시 파일 정리·잘못된 동·호 표기를 검증했다. Frontend 68개 검사, lint 및 배포 빌드를 통과했다. 실제 OpenAI·공공 API는 이 검증에서 호출하지 않았다. 실제 발급 PDF의 인식 품질 검증은 사용자가 자료를 등록하고 동의한 뒤 별도로 수행한다.

운영 전환 과제: 보존·삭제 기간과 사용자 고지, 외부 처리 정책·개인정보 최소화 검토, 업로드 요청 제한·악성 PDF 대응, 영속 저장소 백업/복구·권한, 여러 Backend 간 작업 잠금·중복 실행 제어·내구성 있는 큐. 기능 확장 과제: 표제부/전유부 관리번호 관계와 세부 면적·층 비교, 발급 시점 차이 처리, 건축물대장 결과의 전체 분석 입력 버전·위험 정책 반영.

공식 참고: [전유부 서식](https://www.law.go.kr/LSW/flDownload.do?bylClsCd=110202&flSeq=104934805&gubun=), [표제부 서식](https://law.go.kr/LSW/flDownload.do?flSeq=104934439&gubun=), [위반건축물 기재 규칙 제8조](https://www.law.go.kr/lsLinkCommonInfo.do?lspttninfSeq=105390).

### 2026-10-26 문서 분석 통합 및 등기사항증명서 이력

- 건축물대장 분석 화면은 결과를 첨부 폼 위에 표시하며 파일 선택 후 분석 버튼 한 번으로 등록·분석을 순서대로 실행한다. 전송 동의 전에는 호출하지 않는다. 새 분석 실패 시 이전 성공 결과와 원본 다운로드를 유지한다.
- POST /api/listings/{listingId}/building-register/analysis 는 multipart files, consent=true, requestId(UUID)를 받는다. V24의 analysis_request_id로 동일 요청의 유료 작업 중복 실행을 방지하며 진행 중인 다른 문서 작업을 차단한다. 기존 개별 등록·분석 API는 유지한다.
- 등기사항증명서에 문서 이력, 파일 분석 상태·처리 시각, PDF 다운로드를 추가했다. GET /api/listings/{listingId}/registry-documents 는 소유자의 이력만 제공한다. GET /api/listings/{listingId}/registry-facts?documentId= 는 선택한 성공 문서의 결과를 조회하며 다른 매물 문서를 거절한다. PDF 다운로드는 기존 인증 경로를 이용하고 Cache-Control: no-store를 적용한다.
- 과거 문서 선택과 다운로드는 새 분석을 실행하지 않는다. 실패한 새 문서와 기존 성공 문서·위험 분석을 보존한다. 실문서·실제 AI 호출 없이 합성 PDF와 모의 AI로 검증한다.
### 2026-10-26 건축물대장 위반 표시의 안전성 분석 반영

- 최신 대장 PDF의 '변경 전 자료' 오표시 원인은 공공 API 재조회/등기 비교 정보 변경까지 문서 자체의 교체로 판단한 데 있었다. 파일 상태 응답의 stale은 최신 첨부 이력·매물 주소/상세주소/건물 유형·소유자 일치 여부로 판정한다. 실행 중 문서 작업의 엄격한 비교 문맥 검증과 오래된 응답 차단은 기존 current 판정으로 유지한다. 최신 PDF 분석 완료 시 점검 현황 02는 파일 분석 완료와 완료 아이콘으로 표시하고 별도 API 실패가 문서 실패를 덮지 않는다.
- 사용자의 최종 결정에 따라 기존 결과에 새 재분석 필요 표시를 추가하지 않고 자동 재분석하지 않는다. 안전성 분석 버튼은 등기 분석이 준비된 소유자에게 계속 제공한다. 수동 실행 때 최신 성공 대장 분석의 MARKED를 BUILDING_VIOLATION / HIGH / 50점 위험요소 한 건으로 반영한다. 여러 파일/페이지의 중복 위반 표시는 한 건으로 묶으며 전체 합계 상한 100점을 유지한다. 기존 40~69.99점 HIGH 구간에 따른 50점 기준이며 이행·시정 여부를 법적으로 확정하지 않는다.
- 표제부/총괄표제부 위반 기재는 해당 호실 관련성 추가 확인을 설명한다. NO_MARK_VISIBLE·UNKNOWN만으로 위험요소를 만들거나 적법성을 확정하지 않는다. 필수 대장이 없는 구 이력/다른 매물 주소 문맥은 반영하지 않는다. 새 분석 실패로 기존 확인된 위반이 사라지지 않도록 가장 최근 성공한 자료를 유지하고, 새로운 성공 자료가 있으면 그 자료로 교체한다. API 재조회만으로 PDF의 위반 사실을 배제하지 않는다.
- V26은 건축물대장 입력 식별값을 risk_analyses에 추가하고 신규 위험요소 코드·HIGH 50점 정책행만 추가한다. 기존 정책 버전/엔진 버전·다른 요소 점수·기존 분석행은 변경하지 않는다. 식별값은 문서 변경 후 수동 실행 시 기존 결과를 잘못 재사용하지 않도록 사용하며 GET 재분석 안내 판정에는 추가하지 않는다. 실제 PDF 재전송·공공 API 재조회는 필요 없다.
### 2026-10-26 법인 소유자 지원 및 건축물대장 미발견 문구

- 등기사항증명서 추출 schema·프롬프트에 entityType(PERSON/CORPORATION/UNKNOWN)을 추가했다. 기존 주민등록번호 형식만 허용하던 검증을 소유자 유형별로 분리한다. 개인은 기존 생년월일 6자리-별표 7자리만 허용하고 완전한 주민번호를 받지 않는다. 명시적 법인은 문서에 기재된 법인등록번호의 6자리-7자리(원문 마스킹 포함)를 허용하며 미기재/인식 불가 시 null로 보존한다. 사업자등록번호·대표자 주민번호·추정 번호로 대체하지 않는다.
- V27은 property_owners에 owner_entity_type·corporate_registration_encrypted를 추가하고 기존 개인 식별정보 컬럼의 NOT NULL 제약을 완화한다. 법인은 개인 주민번호 암호문/생년월일 해시를 생성하지 않으며 법인등록번호는 별도 PGP AES256 암호화 컬럼에만 저장한다. 기존 소유자 데이터는 UNKNOWN으로 보존하고 원문 번호를 재해석/변경하지 않는다. 기존 Owner 생성자와 개인 분석 경로는 호환된다.
- 소유자 전용 registry-facts 응답에는 entityType만 추가하며 개인/법인 식별번호·암호문·해시는 반환하지 않는다. 법인은 화면에서 소유자 법인명·법인등록번호(보호로 비노출)로 표시한다. 법인의 실재·대표권·임대 권한을 자동 검증 완료로 간주하지 않는다. 공유자 기능 보류는 유지한다.
- 사용자의 최종 화면 결정: 위반 발견 시 기존 표현을 유지한다. 모든 첨부 대장의 위반 표시가 NO_MARK_VISIBLE인 경우 요약 문구만 '위험요소가 발견되지 않았습니다.'로 표시한다. 일반 변경 이력/참고 기재·총괄표제부와 개별 호실의 비교 차이만으로 포괄적 추가 확인 요약을 띄우지 않는다. 상세 원문/대조 이력은 보존한다. UNKNOWN은 위험 미발견으로 바꾸지 않고 인식하지 못한 파일·페이지를 명시한다. 필수 문서 누락도 미발견으로 표시하지 않는다.
- 62번 기존 실패 기록·64번 저장 결과를 임의 변경하거나 실제 OpenAI 재전송을 하지 않는다. 법인 인식의 실제 문서 검증은 사용자가 다음 분석을 실행할 때 진행한다. 공공 API는 계속 사용자 조회 버튼으로만 실행한다. 법인 식별정보도 기존 운영 전 보존/삭제·백업/접근통제 정책에 포함한다.
