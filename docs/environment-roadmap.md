# SafeHome 환경 정리 및 운영 전환 계획

기준일: 2026-10-14

## 문서 사용 원칙

- 이 문서는 SafeHome 개발환경과 운영 전환 범위를 정하는 단일 기준 문서입니다.
- 모든 개발 작업은 저장소 루트의 `AGENTS.md` 지침에 따라 이 문서를 먼저 확인합니다.
- 환경, 의존성, 포트, 인증, 배포 또는 데이터 저장 정책이 바뀌면 해당 구현과 함께 이 문서를 갱신합니다.
- 개발 중 새로 발견된 운영 과제는 아래 운영 전환 목록에 누적합니다.
- 소프트웨어 구성도 PowerPoint는 개별 변경 때마다 갱신하지 않고, 사용자가 요청할 때 현재 구현 기준으로 최종 갱신합니다.

## 지금 적용한 항목

### 개발 6단계 1차 구현 (2026-10-20)

- 별도 Integration Server: Java 21 / Boot 4.1.1 / Spring AI 2.0.1, 기본 127.0.0.1:8090.
- 내부 REST와 MCP는 X-SafeHome-Integration-Token으로 보호하며 32자 이상 토큰을 환경변수로 주입합니다.
- 공공 API 디코딩 키는 BUILDING_HUB_SERVICE_KEY로 주입하고 저장소에 넣지 않습니다.
- Backend client는 safehome.integration.enabled=true일 때만 등록합니다. 기존 자동 분석 흐름에는 아직 연결하지 않습니다.
- DB·Compose·Frontend 계약은 변경하지 않습니다. Redis 캐시는 실제 API 명세와 전체 조회 검증 뒤 도입합니다.
- 상세 작업·검증 현황은 docs/stage6-plan.md와 integration-server/README.md에 기록합니다.
- Integration Server와 선택적 Backend client를 원본에 적용했습니다. 자동 분석 연계는 후속 검증 항목입니다.
- 공식 건축HUB 가이드와 실제 응답을 대조해 전유부 → 기본개요 → 표제부 관리번호 관계를 검증했습니다.
  개봉동과 잠실동 사례는 전체 수집 후 MATCHED였으며, 자동 분석 연계는 별도 작업입니다.
- 자동 연계 준비 1·2단계: 매물 주소 검색의 선택 유형·선택 주소·확정 지번·법정동 코드·시군구 코드·선택 안함 여부를
  Backend에서 형식과 상호 일치를 검사해 `listings`에 저장합니다. 직접 입력·기존 매물에는 검색 근거가 없으며,
  기본 주소를 수정하면 기존 검색 근거를 지웁니다. 브라우저가 제출한 근거는 공급기관의 서명된 증명이 아닙니다.
- 건축HUB 입력 생성기는 매물 상세주소와 검증된 등기부 판독값의 동·층·호 원문과 정규화 값을 구분합니다.
  일반 사용자가 층을 생략하면 등기부의 명시적 층을 사용할 수 있으나, 양쪽 모두 없거나 충돌하면 호출 입력을 만들지 않습니다.
  검색 결과의 모호한 지번이나 `지층`만으로 층번호를 추정하지 않습니다. 외부 호출·결과 저장·화면 표시는 후속 단계입니다.

| 배포 이미지 기반 | Frontend 다단계 Dockerfile과 Nginx 설정, SPA fallback, `/healthz`, 보안 헤더 구성 | 운영 배포 방식을 선택할 때 검증된 이미지 기반 사용 가능 |
| 개발 서버 관리 | `scripts/start-dev.ps1`, `stop-dev.ps1`, `status-dev.ps1`로 전체 기동·종료·상태 확인 | 개발자마다 다른 수동 실행 절차를 하나로 통일 |

## 개발 중 계속 지킬 기준

- 새 의존성 설치 후 `npm audit`와 `npm run check`를 실행합니다.
- 화면에서 Backend 주소를 직접 입력하지 않고 `/api` 상대 경로를 사용합니다.
- 실제 API 키, 암호, 운영 도메인은 저장소 파일에 기록하지 않습니다.
- Backend API 계약이 변경되면 Frontend 타입과 오류 처리를 함께 갱신합니다.
- PDF 업로드 크기 제한은 Frontend, Nginx, Backend에서 같은 값으로 관리합니다.
- 회원 비밀번호는 12자 이상 영문·숫자·특수문자 조합으로 제한하고 3개월마다 변경합니다.
- 비밀번호 변경 시 현재 및 직전 비밀번호 재사용을 차단하고 기존 로그인 토큰을 폐기합니다.
- 매물 등록 주소는 지번·도로명 구분 없이 사용자가 선택한 기본 주소와 직접 입력한 상세주소를 나누어 저장하고, 합친 전체 주소로, 판독된 등기부의 지번 또는 도로명 주소와 일치 여부를 검증합니다.
- `listings.address`는 기본 주소, `listings.detail_address`는 상세주소를 저장합니다. `properties.address`와 `properties.road_address`는 등기부에서 판독한 동일 부동산의 지번 주소와 도로명 주소를 각각 보관하므로 통합하지 않습니다.
- 주소 검색은 카카오 우편번호 서비스를 사용하며 사용자가 지번 또는 도로명 주소를 선택할 수 있고 합성 테스트 주소는 직접 입력할 수 있습니다.
- 회원가입 이메일은 로컬부와 도메인 구조, 연속된 점, 도메인 라벨과 최상위 도메인 형식을 화면과 서버에서 함께 검증합니다.
- 금액 입력은 음수를 허용하지 않고 화면에서 천 단위 쉼표를 표시합니다.

- 본인이 등록한 등기부 판독 대기·실패 매물은 수정·삭제할 수 있습니다. 판독 중과 성공 이후에는 제한하며 삭제 시 첨부 PDF도 정리합니다.

## 운영 전환 시 완료할 항목

아래 항목은 운영 도메인, 클라우드, 사용자 규모가 정해진 뒤 결정해야 합니다. 단, 공개 서비스 시작 전에는 모두 완료해야 합니다.

### 네트워크와 배포

- 운영 도메인과 DNS를 연결하고 TLS 인증서를 적용합니다.
- Load Balancer 또는 Reverse Proxy에서 HTTPS 종료, HTTP→HTTPS 전환, HSTS를 설정합니다.
- Frontend와 Backend 이미지를 빌드·검사·배포하는 CI/CD와 이미지 저장소를 구성합니다.
- PostgreSQL과 Redis는 사설 네트워크에 두고 인터넷 포트를 열지 않습니다.
- 개발용 `docker-compose.yml`을 운영 배포 파일로 그대로 사용하지 않습니다.

### 비밀정보와 데이터 보호

- 운영 DB 암호, API 키, 암호화 키를 Secret Manager에 저장하고 주기적으로 교체합니다.
- 등기 PDF 저장 위치를 영속 Object Storage로 전환하고 서버 측 암호화, 접근 정책, 보존·삭제 정책을 적용합니다.
- PostgreSQL 자동 백업, 시점 복구, 복구 훈련과 Redis 장애 복구 방식을 확정합니다.
- 개인정보와 민감 문서의 로그 기록 범위를 점검하고 마스킹 정책을 적용합니다.

### 인증과 외부 공격 대응

- 브라우저 인증 토큰을 HttpOnly·Secure·SameSite 쿠키 방식으로 전환하고 CSRF 정책을 함께 적용합니다.
- 로그인, 회원가입, 파일 업로드, 분석 요청에 Rate Limit과 계정 잠금 또는 추가 인증 정책을 적용합니다.
- 운영 CORS 허용 주소를 실제 서비스 도메인으로 제한합니다.
- 이메일 인증, 비밀번호 재설정, 계정 삭제와 개인정보 처리 흐름을 완성합니다.
- 공개 전 취약점 검사와 주요 사용자 흐름 보안 검토를 수행합니다.

### 안정성과 운영 관측

- Integration Server의 내부 TLS/인증키 순환·Origin 검증, 지속 호출 이력, 다중 인스턴스 호출량 제어를 구성합니다.
- MCP의 잘못된 요청 응답에서 내부 스택 정보가 노출되지 않도록 오류 직렬화를 제한합니다.
- 외부 응답을 스트리밍 수신하면서 크기를 제한하고, 실측 페이지 지연·호출량 기준으로 조회 예산을 조정합니다.
- Redis에는 완전 수집한 원천 데이터와 원조회시각만 캐시하고 실패·부분수집은 저장하지 않습니다.

- 요청 로그, 오류 추적, 지표, 대시보드, 알림과 감사 로그를 구성합니다.
- 등기 분석 작업을 영속 Queue에서 처리하고 재시도, 중복 방지, 실패 작업 복구를 구현합니다.
- 예상 동시 사용자와 PDF 크기를 기준으로 부하 테스트를 수행하고 자원 한도를 정합니다.
- Health/Readiness 점검과 무중단 배포·롤백 절차를 검증합니다.
- 장애 대응 연락 체계, 운영 매뉴얼, 데이터 복구 목표(RPO/RTO)를 문서화합니다.

## 운영 전환 판정 기준

다음 조건을 모두 만족하면 공개 운영 전환이 가능합니다.

1. 운영 도메인 HTTPS 접속과 보안 헤더 검증 완료
2. 비밀정보가 저장소와 배포 파일에 평문으로 존재하지 않음
3. DB·Redis가 외부 인터넷에서 접근되지 않음
4. 회원가입부터 매물 등록, PDF 처리, 안전 분석·재분석까지 운영 환경 통합 테스트 통과
5. 백업 복원 시험 통과
6. 모니터링과 장애 알림 수신 확인
7. 보안 점검의 출시 차단 항목이 모두 해소됨
8. 배포 실패 시 이전 버전으로 되돌리는 절차 검증 완료
