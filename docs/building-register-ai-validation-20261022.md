# 건축물대장 실제 AI 판독 검증 — 2026-10-22

## 범위·승인·실행

사용자가 명시 승인한 6회로 실제 PDF 11개(27페이지)를 서비스와 동일한 OpenAiBuildingRegisterParser·gpt-4.1·Responses API·store:false·구조화 출력으로 판독했다. 자동 재시도하지 않았다. 기존 매물·등기사항증명서·위험 분석 DB를 변경하지 않는 독립 판독기 검증이다. 기존 등기사항증명서를 전송하지 않았다. 비용·토큰 사용량은 이 도구에서 수집하지 않았으므로 금액을 추정하지 않는다.

원본 응답에서 얻은 추출 JSON·평가·파일 해시·호출 시작 기록은 저장소 밖 `D:/safehome-data/integration/ai-building-tests/20261022-six-samples-01`에 보관한다. 실제 문서·개인정보·키·토큰·응답 원문은 Git에 추가하지 않는다. API의 전체 응답 원문은 기록하지 않았으며 Extraction만 저장했다.

최초 검증 도구가 호수 문자열의 완전 일치를 요구해 05·07의 장식된 층/호 표기를 불일치로 집계했다. 기존 서버의 호수 정규화 비교로 재확인하니 6건 모두 호실은 일치했다. 이는 문서 번호 출처·파일 누락 문제와 별도로 구분하며 잘못된 호실 판독으로 보고하지 않는다.

## 수정·외부 호출 없는 재검증

- 각 PDF 앞에 원본 fileIndex와 전체 파일 수를 명시하고 최종 파일별 누락 점검을 지시한다. 표제부·총괄표제부도 각각 별도 entry로 추출하도록 명확히 했다.
- 복층의 전유부분은 각 행별 층·면적을 별도 entry로 보존하도록 했다. 합계로 대체하거나 공용면적과 섞지 않는다. 같은 호실의 서로 다른 층 표기를 다른 호실로 판단하지 않도록 정규화 비교를 보완했다.
- 모든 입력 PDF의 결과 존재와 파일/페이지 범위를 서버에서 검증한다. PDF의 텍스트 머리말에서 신뢰할 수 있는 대장 종류를 읽을 수 있으면 추출 종류와 대조한다. 한 PDF에 여러 대장이 합쳐진 경우의 종류 집합도 허용한다. 스캔·특이 서식 등 머리말을 확인할 수 없는 자료는 종류 비교만 생략하고 파일 누락·페이지 범위 검사는 유지한다.
- 판독 누락은 PARSER_INCOMPLETE, 출처의 대장 종류 불일치는 PARSER_SOURCE_MISMATCH로 차단하고 화면에 완료된 결과가 아님을 알린다. 자동 재호출하지 않는다.
- 저장된 실제 응답 6건을 네트워크 호출 없이 재검증했다. 01은 유지되고 5개 복합 파일 누락 결과는 모두 차단됐다. 실제 11개 PDF에서 표제부/전유부 머리말 종류를 구분했다.
- Backend 관련 31개 검사·JAR 빌드, Frontend 75개 검사·lint·배포 빌드를 통과했다. 파일 누락·출처 뒤바뀜·증거 페이지·합쳐진 PDF·복층 행 보존을 회귀 검사에 추가했다.
